## Q01 · Perplexity 与局限

### 定义

Perplexity = 模型对测试集的不确定性，等于交叉熵的指数：

$$
\mathrm{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N} \log P(x_i \mid x_{1:i-1})\right)
$$

PPL 越低，模型在给定评测文本上的平均负对数似然越低，不等于对任意预测都“更确定”：若自信地预测错误 token，真实 token 概率很低，PPL 反而很高。

这个“有效候选数”解释只在平均负对数似然的指数意义下成立，不表示模型真的均匀地在 PPL 个 token 中选择。PPL 对少量极低概率 token 很敏感，也会受到 BOS/EOS、空格、截断和是否按 token 加权的影响。

### 局限

- **不能跨 tokenizer 比较**（不同分词导致 N 不同）
- **不反映指令遵循能力**（PPL 低不等于回答好）
- 对**校准、风格、安全**全无感知

→ 现代 LLM 评测**不再以 PPL 为主**，更多看下游任务表现。

若必须跨 tokenizer 比较，可报告按 byte/character 归一化的 negative log-likelihood（如 bits-per-byte），但前提是对同一原始文本计算完整概率；不同模型的规范化、不可编码字符和上下文窗口仍要对齐。

## Q02 · 主流基准

| 基准 | 测什么 | 形式 |
|---|---|---|
| **MMLU** | 通用知识（57 个领域） | 多选 |
| **GSM8K** | 小学数学推理 | 自由生成 + 答案 |
| **MATH** | 高中竞赛数学 | 自由生成 + 答案 |
| **HumanEval** | 代码生成 | pass@k |
| **MBPP** | Python 编程 | pass@k |
| **HellaSwag** | 常识推理 | 选择 |
| **TruthfulQA** | 真实性 | 选择 |
| **BBH** | Big Bench Hard 推理 | 多种 |
| **HELM** | 综合（公平、效率、健壮性） | 综合 |
| **C-Eval / CMMLU** | 中文通用知识 | 多选 |
| **AGIEval** | 高考 / 公务员等中文考试 | 选择 |

### 追问

- **Q：pass@k 怎么计算？**
  A：让模型生成 k 个解，**至少有一个通过单测就算 pass**。无偏估计公式：

  $$
  \text{pass@k} = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}
  $$

  其中 n 是采样总数，c 是通过数。

  这里不是“实际只生成 k 个然后看一次”，而是先生成 $n$ 个候选，再估计从其中无放回抽取 $k$ 个时至少一个通过的概率；当 $n-c < k$ 时该值为 1。比较模型时还必须固定采样温度、测试 harness、超时和依赖版本。

- **Q：基准容易刷分怎么办？**
  A：精确 hash 只能发现完全重复；还需做规范化后的近重复、题目/答案/解析匹配及来源检查。使用更新的题目、隐藏测试集和人类盲评可增加互补证据，但任何单一方式都不能证明没有污染，详见 Q07。

## Q03 · LLM-as-Judge 偏差

用 LLM（通常 GPT-4）当评委给两个回答打分。

### 已知偏差

| 偏差 | 现象 | 缓解 |
|---|---|---|
| **位置偏好** | 偏向第一个回答 | 双向交换打两次 |
| **冗长偏好** | 偏向长答案 | 长度分桶、内容等价反例与人工校准；不能把所有长答案都惩罚 |
| **自我偏好** | 偏向同模型生成的答案 | 隐藏身份、使用独立 Judge，并验证残余偏差 |
| **风格偏好** | 偏向格式漂亮的 | 在 prompt 里强调内容优先 |

### 替代方案

- **Chatbot Arena**：人类盲评 + ELO 评分
- **MT-Bench**：80 道多轮问题；原始研究包含单答案评分、成对评判等 Judge 设置，不能一概等同于两两对决

“换更强 Judge”不能消除系统性偏差。更稳妥的流程是：先定义可操作 rubric 和分项分数；交换答案位置并隐藏模型身份；使用多 Judge 或人类标注校准；报告与人类的一致率和置信区间；对分歧样本人工复核。若两个候选差异很小，强迫二选一会放大噪声，应允许 tie。

### Judge 怎样校准，而不只是“多评几次”？

先构建按任务、长度、难度分层的人类复核集，允许平局和无法判断。将 Judge 与人类的比较拆成胜/负/平的混淆矩阵，检查它是否特别偏向某个长度段、格式或模型家族；总体一致率可能掩盖某类系统性误判。

候选交换位置后仍应按照真实候选身份合并结果；发生相反判决时标记不稳定或交由复核，不能把两次判断当作两个独立题目扩大样本量。针对长度偏差，可以配对构造“同内容的简洁版与重复版”，或报告控制长度后的结果；不能通过截短长答案破坏内容后再声称公平。

Judge 的模型版本、rubric、温度、解析失败处理都要固定。换 Judge 后重新校准，原阈值不能自动沿用；训练用的奖励模型也不应成为唯一评委。来源：[Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685)。

## Q04 · Hallucination 检测

### 类型

| 类型 | 例子 |
|---|---|
| **事实性幻觉** | 编造不存在的论文 / 人物 |
| **逻辑性幻觉** | 算错数 / 推理跳步 |
| **指令幻觉** | 明明要求中文却答英文 |

### 检测方法

- **自洽性**：多次采样看是否一致（SelfCheckGPT）
- **外部检索**：检索证据验证（RAG 框架）
- **NLI 蕴含**：用 NLI 模型判断答案是否被 context 蕴含
- **模型置信度信号**：token 概率、语义熵或多次采样分歧可作为风险特征，但低概率不等于幻觉，高概率也可能是模型自信地记错，不能单独当事实验证器

检测应先明确“相对于什么为真”：closed-book 事实要对照可信外部来源，RAG 忠实度要判断每个 claim 是否被给定 context 蕴含，逻辑/数学错误则需要执行器或验证器。把三类混成一个 hallucination 分数会让诊断失去意义。

## Q05 · Lost in the Middle

### 现象

LLM 在长上下文中，**对开头和结尾的信息利用率高，对中间的低**——典型 U 型曲线。

### 缓解

- 把**最重要的 context 放开头或结尾**
- 用 RAG **筛选少量相关 chunk**（少而精）
- 用支持长上下文的模型（Gemini-1.5、Claude-3 等显著缓解）
- 在评测中显式测试中间位置（Needle-in-a-Haystack）

Needle 测试只能说明模型能否定位一个人工插入事实，不能代表多文档综合、冲突证据和长链推理。应同时改变证据位置、上下文长度、干扰项数量和问题类型，并报告各位置分桶曲线，而不是只报“支持 128K”。

## Q06 · 提升是否可信：配对比较与置信区间

### 为什么要比较同一批题目的差值？

设模型 A、B 在同一题上的分数为 $a_i,b_i$，令 $d_i=b_i-a_i$。关注的是 $\bar d$，而不只是分别计算两个均值。配对设计保留了题目难度的共同影响；把两套结果当独立样本，会丢失相关性信息。

在题目独立同分布、样本量足够、均值近似正态等条件下，可粗略写为：

```math
\bar d=\frac1n\sum_i d_i,\qquad
s_d^2=\frac{1}{n-1}\sum_i(d_i-\bar d)^2,\qquad
SE(\bar d)=\frac{s_d}{\sqrt n}
```

近似 95% 区间为 $\bar d\pm1.96SE$。这是大样本近似；小样本、稀疏胜负、偏态指标或复杂采样不能机械套用，需合适的 t 区间、精确方法或重采样。

**手算例子**：100 道二元得分题，B 独对 A 独错的有 15 道，A 独对 B 独错的有 5 道，其余相同。平均提升为 10 个百分点；$s_d^2=(20-100\times0.1^2)/99=19/99$，标准误约 4.38 个百分点，正态近似区间约为 $[1.41,18.59]$ 个百分点。这说明点估计 10 并不意味着真实提升已被精确测到。

二元配对结果还可用 McNemar 检验；其信息来自两种不一致结果，而不是总正确数。显著性不等于实际收益大小，也不代表新分布上仍然有效。

### Paired bootstrap 如何做？

从原来的 $n$ 道题中有放回抽取 $n$ 个题目索引，每次同时取 A/B 在这些题上的记录，再计算差值。重复后取差值分布的分位数，可得到 percentile bootstrap 区间；它也有有限样本与覆盖率局限，并非任意数据上的精确保证。

重采样单位必须与独立性假设一致。同一道题的多个采样回答、同一文档衍生的多个问题、同一用户的重复交互，往往相关；应按题目/文档等簇一起重采样。直接把所有 token 或回答当独立样本，会虚增样本量、缩窄区间。训练随机种子的波动与评测题目的抽样不确定性也不同，多 seed 结果应另行报告。

相关接口及统计定义可参考 [SciPy bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html) 与 [statsmodels McNemar](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html)。

### 胜率与 pass@k 的分母要说清楚

允许平局时，可以报告 win/tie/loss 三项，也可以预先定义 $\mathrm{winrate}=(W+0.5T)/n$；只在非平局样本上计算 $W/(W+L)$ 是另一个指标。解析失败、超时、拒答的处理同样会改变分母，不能训练前后换规则。

pass@k 应先按题目估计，再按预先约定的任务权重汇总；同题候选不是彼此独立的“题目”。固定预算下比较 pass@1、pass@k 和 best-of-N，还要报告采样数量、总生成 token、验证器成本与最终选择规则。

## Q07 · 去污染、模型选择与可复现报告

### 数据泄漏不只有“训练集出现原题”

| 泄漏形式 | 检查思路 |
|---|---|
| 原文重复、空格或格式变体 | 精确 hash、规范化文本匹配 |
| 大段重合、答案解析泄漏 | n-gram/近重复检索，分别检查题干与答案 |
| 改写、翻译、同模板变体 | 语义检索后人工复核，按模板/来源分组 |
| 测试反馈进入数据回流 | 记录来源与使用目的，隔离最终测试集 |
| 反复按测试分数挑 checkpoint | 使用验证集做选择，保留一次性最终测试 |

语义相似不自动等于泄漏；公共事实相同也不等于重复训练实例。应记录判定规则和疑似污染比例，并分别报告清理前后结果。无法访问基座训练语料时，只能说明可检查范围，不能宣称“已经证明无污染”。

### 为什么调参也会用掉测试集？

如果不断比较几十个模板、奖励权重或 checkpoint，再选测试分数最高的一个，即使没有把测试题用于反向传播，也会对该测试集选择性过拟合。应把超参选择与最终报告分开；多指标/多比较时预先指定主要指标，必要时控制多重比较或增加独立验证。

时间切分能减少未来数据泄漏，但也引入分布变化。评估时应明确是在测试同分布泛化、时间外推、未见模板还是新领域，而不是把它们混成一个分数。

### 最小可复现报告

- 模型与 adapter 的精确版本、tokenizer/chat template、量化和推理后端。
- 评测集版本、样本数、切分与去污染规则；不公开的材料说明访问边界。
- prompt/few-shot 设置、温度、top-p、最大长度、停止条件、seed 和采样次数。
- 评分器/单测/依赖版本，Judge rubric，超时、解析失败与拒答的处理。
- 点估计、置信区间方法、独立采样单位、分任务/长度/难度结果。
- checkpoint 选择依据、已尝试的主要配置，以及与基线相同的计算预算口径。

“平均分更高”只是起点；可信结论应能回答提升来自哪些题、有没有回归、是否超过噪声、增加了多少成本。对后训练还应同时报告训练奖励和独立任务指标，避免用代理分数自证。
